# TVBox PC

一个基于 **TVBox 开源接口协议** 实现的 Windows 桌面影视客户端。2.5.0 起界面**严格照安卓 TVBox 的布局**重排：
左上「影视」+ 右上时钟 → 一排五个方块图标（点播 / 搜索 / 直播 / 收藏 / 设置）→ 首页左栏章节菜单（最近观看 / 更新推荐 / 按站点浏览）→ 右侧海报墙；
详情页是「左白边宽屏剧照 + 右片名/评分/站源年份地区类型/导演演员 + 胶囊按钮 + 线路行 + 集数行 + 倒序分页行」；搜索页是「左关键字 + 7 列键盘、右热搜胶囊」；播放器底部是整宽按钮条 + 整条进度。

本项目是「空壳播放器」：软件本身不含任何影视资源，只负责加载你填写的接口（json），
解析接口里的站点、分类、搜索、详情、剧集与直播地址，然后用内置播放器播放。

Kodi 那边只借了「操作界面」：媒体库、刮削器、插件、皮肤系统、PVR 这些一律没有实现，
功能面只保留 TVBox 的那一套。2.4.0 起界面本身也换成安卓 TVBox 的排法。

> 接口与内容由使用者自行提供。请遵守当地法律法规，使用合法授权的影视来源。
> 本项目只复刻 TVBox 的协议与交互，不包含 TVBox 原项目的 APK、spider jar 或任何第三方资源。

## 功能

| 模块 | 说明 |
| --- | --- |
| 接口管理 | 填 URL、粘贴 json 文本、或**直接选本地 txt / json 文件**（文件内容整段存进软件，之后不再依赖原文件）；本地保存多个接口，一键切换，支持多仓（自动提示选线路，可逐条探测 / 合并所有可直连站点）。**接口会记住**：地址 / 文件内容 / 多仓选过的线路都落库，重启自动沿用 |
| 首页推荐 | 左栏菜单选「最近观看」或「更新推荐」；更新推荐会并行拉取最多 10 个站点首页，各站点轮流取一条铺成海报墙（最多 60 条，带站点角标 + 评分） |
| 分类浏览 | 站点选择 → 分类标签 → 分页网格；**上一页 / 下一页放在顶部**，遥控器不用滚到底 |
| 搜索 | 聚合当前接口下所有可搜索站点，结果按站点分组；「关键字…」输入 + **7 列屏幕键盘**（首行是功能键：退格 / 光标左右 / 清空 / 搜索 / 收键盘 / 回主页），右侧「热搜」是接口里的真实片名胶囊，点一下就搜 |
| 详情 | **左白边 16:9 剧照 + 右片名 / 评分 / 站源·年份·地区·类型 / 导演 / 演员**，四个胶囊按钮（播放 · 简介 · 收藏 · 换源），下面线路行、集数行、`倒序 | → | 1-20 / 21-40` 分页行（每页 20 集）；点「简介」展开简介面板 |
| 播放 | HLS（m3u8）走 hls.js，mp4/flv 走原生播放；**自绘控制条**（进度条 + 一排功能键：上一集/播放暂停/下一集/后退 10s/前进 10s/倍速），支持续播、自动下一集、选集抽屉、全屏 |
| 解析 | 播放地址不是直链时，先从网页里抠出真实 m3u8/mp4（分享页、ckplayer 播放页、iframe），再依次尝试接口里的 `parses` |
| 直播 | 支持 m3u / TVBox txt 直播源；**左侧分组栏 + 右侧频道墙**（三位频道号），多个直播源用标签页切换 |
| 收藏 / 记录 | 本地保存收藏与观看进度，首页可续播 |
| 站点体检 | 设置页一键测每个站点的可用性与响应延迟，按快慢排序，接口挑线路时很实用 |
| 接口诊断 | 一键告诉你「为什么刷不出内容」：接口 HTTP 状态、json 顶层字段、每个站点是能直连还是被跳过、实测 `ac=list` 的返回，最后给出结论 |
| 快捷键 | 播放器内 空格播放/暂停、←→ 快退快进 10 秒、↑↓ 音量、F 全屏、Esc 退出 |
| 网络 | 可自定义 User-Agent、Referer（部分源站会校验） |

## 界面与操作（安卓 TVBox 排法，遥控器优先）

- **布局**：和安卓 TVBox 一样。第一行：圆形 TV 标 + 「影视」；第二行：**五个方块图标**（点播 / 搜索 / 直播 / 收藏 / 设置，图标在上文字在下，选中项白描边）；下面首页内容区是**左栏章节菜单**（最近观看 / 更新推荐 / 按站点浏览 / 刷新内容）+ 右侧海报墙（一行 5–6 张）。右上角不再显示接口 chip 和时钟（那两样在首页属于无效信息）。
- **标题栏按需隐藏**：系统那条标题栏已经去掉，右上角是自绘的最小化 / 最大化 / 关闭；内容往下滚时**方块图标行自动收起**只剩品牌与时钟；按 `↑` 回顶栏、鼠标移到屏幕顶部、或滚回顶部时自动展开。顶部 36px 是透明拖动区，可以拖窗口。
- **深色 / 浅色 / 跟随系统**：**启动默认浅色**；设置页「外观」可切浅色 / 深色 / 跟随系统，立即生效并记住（跟随系统时系统换深浅色这边也立刻跟上）。浅色是白面板 + 浅灰蓝底，播放器始终黑底（看片不该被界面颜色干扰）。启动时先上色再渲染，不会先闪一下黑。
- **应用图标**：浅蓝渐变圆角方块 + 白色播放键，桌面/任务栏/exe 文件本身都是这个图标。
- **海报墙**：卡片左上角是**站点角标**、右上角是更新备注、左下角是**评分**，标题与年份在卡片下方。
- **滚动条**：弹窗、接口清单、诊断、选集抽屉、首页内容区里的滚动条统一隐藏或换成 8px 圆角细条（无系统箭头），不再出现白底那种默认滑块。
- **遥控器尺寸**：整体按 10-foot 放大——方块图标 120px 带 44px 线条图标、章节菜单 23px、海报约 170px 宽、按钮/输入框统一加大、焦点环 3–4px，坐远也看得清、点得准。
- **焦点串联**：海报 `↑` → 顶部方块图标（左右移动、`Enter` 切页）、`←` → 左栏章节菜单（上下移动、`Enter` 切章节）；章节菜单与图标行都能回到海报墙。三个层都是白描边 + 轻微放大，自动滚动到可见区域。
- **播放器**：全黑底 + 顶部渐变信息条（返回、片名 · 线路 · 集数、右侧「选集 / 全屏」）+ **底部整宽控制条**：一排功能键**左对齐**排开（上集 / 下集 / 暂停 / 后退10s / 前进10s / 倍速 / 选集 / 全屏），下面一整条进度 + 左右时间。鼠标一动浮层浮现，4 秒不动自动隐藏；选集抽屉从右侧滑出。
- **播放器遥控操作**：`←→` 快退快进 10 秒、`↑↓` 音量、`空格/Enter` 播放暂停、`↓` 进底部功能键排（`←→` 选键、`Enter` 执行、`↓` 回视频）、`Backspace/Esc` 退出；选集抽屉打开时方向键按两列网格走，`Enter` 换集，`Backspace/Esc` 收起。
- **直播页**：左栏是分组（名称 + 该组频道数，选中项渐变高亮），右栏是频道墙（`001` 这种三位频道号 + 频道名，按窗口宽度自动多列）；页面顶部只显示「当前源：xxx」和一个「切换直播源」按钮，进入直播页焦点自动落在左栏分组上。
- **进直播就自动挑能用的源**：优先落到上次解析出过频道的源；如果当前源一个频道都没解析出来，会自动顺延试下一个（最多试 4 个）并提示「已换到 xxx」，不用自己去猜哪个源能用。
- **RTMP 频道会标出来**：桌面播放器（Chromium）只吃 http(s) 的 m3u8 / flv / mp4。频道如果是 `rtmp://`/`rtsp://` 这类，列表右侧会带一个 `RTMP` 小标；点它时会自动在同组里换一个能播的频道，并提示换了哪一个。同组里全都没有 http 地址时，会明确告诉你「这个频道桌面播不了」。
- **切换直播源是次级菜单**：一百多个直播源不再平铺成一大片胶囊，而是点「切换直播源」打开的二级弹窗——**出过频道的那几个排最前面标「可用」**，其余折叠在下面标「未验证」，顶部带关键字筛选，点一条就切过去并重新解析（解析成功的会自动进白名单，下次排前面）。
- **输入框也能聚焦**：设置页的接口地址等输入框也进了焦点序列，`Enter` 即「进框输入」，`Esc` 退出。
- **屏幕键盘按需出现**：搜索页默认只有输入框 + 「键盘 / 搜索」两个按钮，键盘收起来时结果区直接露出来；点「键盘」或在输入框按 `↓` 才弹出 **7 列键盘**（首行功能键：退格 / ‹ / › / 清空 / 搜索 / 收键盘 / 回主页），方向键选字母、`Enter` 输入，第一排按 `↑` 回到输入框，按搜索后自动收起。
- **确认 / 返回**：`Enter` 或 `空格` 执行当前焦点；`Backspace` / `Esc` 逐层返回（播放器 → 弹窗 → 详情 → 分类 → 首页）。
- **鼠标**：光标移到哪一项，哪一项就获得焦点，点一下即执行——和 Kodi 接鼠标的手感一致。
- **F11**：全屏 / 退出全屏；启动默认最大化。
- **播放器内**：空格播放/暂停、`←→` ±10 秒、`↑↓` 音量、`F` 全屏、`Esc` 退出；退出播放器后焦点回到详情页主按钮。
- **输入框内**：方向键、退格交还给文本框，不触发导航。

保留的只有 TVBox 的能力（接口观影 + 直播 + 多接口 + 收藏/记录），Kodi 的媒体库、刮削、插件、皮肤/PVR 都没有做。

## 解析引擎（2.7.0 新增）

影视TV 5.4.2 之所以能跑那些 `type=3` 的站点，是因为它自带 JS 规则引擎。2.7.0 把这套引擎搬进来了：

- `src/renderer/vendor/cat.js` 是从 APK 里原样取出的 TVBox JS 库（`cheerio / jsp / jinja2 / Crypto / CryptoJS` 等都在里面）。
- `src/renderer/jsspider.js` 是宿主：把规则文件里的 `import` 改写成对 cat.js 的引用，注入同步的 `req()` / 异步的 `http()`（渲染窗口 `webSecurity:false`，可以直接跨域），再取规则导出的 `spider` 对象。
- 调用约定和 TVBox 一致：`homeContent / categoryContent / detailContent / searchContent / playerContent`，返回的 JSON 直接进现有的解析链路；播放时先问规则的 `playerContent`，拿不到再走网页嗅探和解析接口。
- 站点的规则地址：先用站点自己的 `spider` 字段，没有就用接口里的全局 `spider`，只认 `.js`。`.jar` 是安卓的 dex 规则，这台电脑上没有 dex 运行时，跑不了。
- 设置页顶部「解析引擎」会直接告诉你当前接口用的是 `.js` 还是 `.jar`，以及有多少站点走 js 规则。

自测：`test\js-rule.js` 会起一个本地假 `.js` 规则站，把首页/分类/详情/搜索/播放解析全跑一遍。

## 数据存在哪

接口（含本地 txt/json 导入的内容）、收藏、观看记录、外观设置都写到
`%APPDATA%\TVBox PC\tvbox-store.json`，同时镜像一份在页面 localStorage 里。
页面跑在 `127.0.0.1` 的随机端口上，localStorage 会随端口变化失效，所以**以磁盘那份为准**：
下次开机先把磁盘数据灌回来，再自动加载上次用的接口，接口和记录都不会丢。

## 运行

**两个包，任选一个**：

- `TVBox-PC-2.6.0-setup.exe`：**安装版**。双击 → 选安装目录（默认 `%LOCALAPPDATA%\Programs\TVBox PC`）→ 自动建桌面和开始菜单快捷方式，装完是一个完整的程序文件夹（`TVBox PC.exe` + `resources` + `locales` 等），控制面板里可以正常卸载。
- `TVBox-PC-2.6.0-portable.exe`：免安装单文件，双击即用，适合放 U 盘。两种包用的是同一份程序与同一个数据目录（`%APPDATA%\TVBox PC`），接口配置通用。

**源码运行**：

```powershell
npm install
npm start
```

**重新打包**（本机账户没有符号链接权限，需绕过 electron-builder 解压 winCodeSign 这一步）：

```powershell
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
npx electron-builder --win dir -c.win.signAndEditExecutable=false
# 再用 rcedit 写入图标和版本信息（可选，不做则是 Electron 默认图标）
npx electron-builder --win nsis --x64 --prepackaged "dist\win-unpacked"       # 安装版
npx electron-builder --win portable --x64 --prepackaged "dist\win-unpacked"   # 免安装版
# 产物：dist\TVBox-PC-2.6.0-setup.exe / dist\TVBox-PC-2.6.0-portable.exe
```

## 接口格式

填进「设置 → 接口地址」的 json，字段与 TVBox 一致：

```json
{
  "sites": [
    {
      "key": "demo",
      "name": "示例站点",
      "type": 1,
      "api": "https://example.com/api.php/provide/vod/",
      "searchable": 1,
      "quickSearch": 1
    }
  ],
  "lives": [
    { "name": "示例直播", "url": "https://example.com/live.txt", "type": 0 }
  ],
  "parses": [
    { "name": "示例解析", "type": 1, "url": "https://example.com/parse?url=" }
  ],
  "flags": ["qq", "youku", "iqiyi"],
  "spider": ""
}
```

多仓写法（加载后会弹窗让你选线路）：

```json
{
  "urls": [
    { "name": "线路一", "url": "https://example.com/api1.json" },
    { "name": "线路二", "url": "https://example.com/api2.json" }
  ]
}
```

多仓也可以是纯 txt，一行 `线路名,地址`（直播 txt 含 `#genre#`，不会被误当成多仓）：

```
线路一,https://example.com/api1.json
线路二,https://example.com/api2.json
```

**选线路弹窗**：多仓动辄上百条线路，弹窗里每条都带状态徽标：

* `用最优线路` —— 快速模式：从第一条开始并发试，碰到「可直连 ≥ 8 个站点」的线路立刻加载，
  百条线路也不用等全部探完；
* `检测各线路` —— 逐条试（并发 8），标出「可直连 N/M」「HTTP 404」「不是 json」「spider 为主」，
  检测完自动按可直连站点数排序；
* `合并可用站点` —— **把所有线路里能直连的 cms 站点抽出来、按 api 去重，合成一个接口**，
  一次拿到全部片源，不用在 110 条线路之间来回切；
* 点某条线路后如果它一个可直连站点都没有，会弹窗说明“全是 spider 规则站”，并给「换一条线路」。

> 实测同一个 110 条线路的多仓：`合并可用站点` 跑完 110 条线路，从其中 27 条里抽到 **170 个可直连站点**
> （去重后），首页拉出 20 条真实影片（如《茜茜皇后第三季》）、分类 20 条，播放正常。
> `用最优线路` 则十几秒落到「六六线路」（15 个可直连站点）。

### 接口会被记住（重启不用重填/重选）

* 填过的接口地址会存下来，下次打开设置页**自动回填**在输入框里，并显示「当前接口 / 来源 / 已记住的线路」；
* 多仓选过哪条线路（或者用了「合并可用站点」），程序记在本地，**下次启动直接加载这条线路/这份合并结果**，
  不再弹「选择一条线路」；想换就在设置页点「换一条线路 / 重新合并」；
* 「已保存接口」列表最多留 30 个，点「使用」随时切回某一份；删除只删本地记录，不影响源站。

直播 txt（TVBox 经典格式，`#genre#` 是分组行，一个频道可用 `#` 挂多个备用地址）：

```
央视,#genre#
CCTV-1,http://xxx/live1.m3u8
CCTV-2,http://a.m3u8#http://b.m3u8
```

### 站点协议说明

* `type: 0` / `type: 1` 的 cms 直连站点（苹果CMS `provide/vod` 接口）—— **支持**
* `api` 以 `http(s)://` 开头 —— 支持
* `type: 3`（spider 规则站，依赖 `spider.jar`）—— **不支持**，桌面版无法执行 Android 端的 jar 规则，
  加载时会自动跳过，并在「检查当前接口」里列出被跳过的站点
* `api` 形如 `csp_xxx` 的站点 —— 同上，跳过

请求参数按 cms 标准：`ac=list` 取分类与首页、`ac=videolist&t=&pg=` 取列表、
`ac=detail&ids=` 取详情、`wd=` 搜索；返回 XML 或 JSON 都能解析。

## 直播源（比安卓版更耐操一点的解析）

支持的写法和容错：

* **m3u / m3u8 清单**：频道名优先取 `tvg-name`，其次 `tvg-id`，最后才是逗号后的名字；
  分组认 `group-title="…"`，也认 `#EXTGRP:分组名`；
  频道前的 `#EXTVLCOPT:http-referrer=…` / `http-user-agent=…` 会被记下来，播放这个频道时自动带上；
  同一个频道连续写多个地址，会被当成备用线路。
* **TVBox txt**：`分组名,#genre#` 分组 + `频道名,url1#url2#url3` 备用地址；全角逗号「，」、行首空格、
  `//` 注释也容错。
* **直播源清单**：如果填的地址返回 `{"urls":[{name,url}…]}`（一份清单里套很多 txt/m3u），
  程序会把它们展开成顶部「直播源」标签，并自动加载第一条。
* **没后缀的直播地址**（`live.php?id=…` 这种）：会先取开头几百字节判断是不是 `#EXTM3U` HLS 清单，
  是就走 hls.js，不是才按直链播；返回 401/403 会明确提示「这个频道需要鉴权」。

## 接口加了却刷不出内容，怎么排查

按这个顺序看，基本能定位到原因：

1. **看顶栏的接口名**：写的是「xxx · 0 个可用站点」就说明站点全被过滤了（见第 2 条）；
   写的是「N 个可用站点」但还是空白，走第 3 条。
2. **点「设置 → 接口诊断」**：它会列出每个站点「能直连」还是「被跳过」以及原因。
   - 被跳过最常见的原因是 `type: 3`（spider 规则站）：这类站点的解析逻辑写在 Android 的 `spider.jar` 里，
     桌面版没法规执行，**只能换接口**，换一个只含 `type: 0 / type: 1` 的苹果CMS 接口。
   - `api` 写成 `csp_xxx` 的站点同理，跳过。
3. **看诊断里的「站点实测」**：全是 `HTTP 403 / 0 字节 / 条目 0` 就说明站点接口本身连不上或挡 UA。
   这时在「设置 → 网络」里填一个该站点的 Referer（例如 `https://站点域名/`）再试；
   程序取数顺序是三层：`net.request`（Chromium 网络栈，TLS 指纹同真浏览器）→ 隐藏浏览器窗口里的
   `fetch`（带 cookie、`Sec-Fetch-*` 等浏览器专属头）→ 仍被挡就如实报 403，并提示用
   「设置 → 用浏览器打开」把接口内容复制下来粘贴加载（真浏览器能过 JS 风控，壳子里过不了）。
4. 接口是 GBK/GB18030 编码的老 XML 源时，程序会按响应头 charset 或替换符自动改用 GB18030 解码，
   不会再因为乱码整页空白。
5. 只带直播的接口（`sites` 为空）不会出现在首页，去「直播」页看。
6. 接口能打开、但站点 `ac=list` 报 403：多半是站点对 Referer 做了防盗链，把 Referer 填成该站点域名
   通常就好了；填完点「站点体检」复测。
7. **剧集地址是一串网页链接（形如 `https://xxx/share/xxxx`）而不是 m3u8**：这多半是「网盘/分享页」播放链接。
   播放器会先抓这个页面，从 HTML 里找出真正的 `index.m3u8?sign=...`／mp4 地址（页面里 `var main = "..."`
   那种写法、`<video src>`、以及 iframe 内嵌页都认），找到就直接播，播放时自动把 Referer 换成该站域名；
   实在找不到才报「不是直接流」。要是页面要求登录/会员才出流，程序这边只能如实报错——那种只能去浏览器里手动看。
8. **直播源里有频道播不出来**：先看左侧有没有解析出频道——
   - 一个频道都没有：多半是地址失效 / 需要 Referer，或格式不是 m3u / txt；换一个源试试。
   - 有频道但点开报错：这类频道常见三种原因，程序会尽量提示——地址已失效（4xx）、
     需要鉴权（401/403）、或对方只给某个 App 的协议（比如只认自家播放器）。同一个频道若写了多条备用地址，
     可以在播放器右侧「频道」里换下一条；m3u 里 `#EXTVLCOPT` 带的 Referer/UA 程序会自动带上。

## 已知限制

* 加密/DRM 流、需要登录鉴权的源站无法播放；
* 部分源站需要特定的 Referer 才能播放，可在设置里全局配置；
* spider（jar 规则）站点不支持，这是 Electron 与 Android 运行环境的根本差异；
* 解析接口只做了「带 url 参数 → 从响应里取 m3u8/mp4」这一种通用模式，特殊私有协议需要自己扩展 `tryParse`。
